# TD sketch project runner

Small Node tooling for ordinary TypeScript projects targeting the embedded avTools
Sketch TOP. No browser dev server, livecode server, or native rebuild is needed
when editing a sketch. The reusable runner imports the existing raw shader generators;
it does not implement another shader language or renderer.

Future development: the [native TypeScript build-tool plan](../../packages/native-webgpu/plans/native-typescript-build-tool-plan.md)
describes a single executable using Rolldown/Oxc and tsrs, followed by automatic
build/watch integration in the C++ TOP/CHOP plugins. It is a proposal; the Node
runner documented here remains the current workflow.

Start with [the two-sketch project](../../apps/td-projects/starter/README.md).
The build tool's dependencies are pinned in `package-lock.json`; install here with
`npm ci`. Its CLI accepts a config file from any project directory:

```sh
node /path/to/avTools/tools/td-sketch-build/cli.mjs dev /path/to/piece/td-sketches.config.ts
```

Use `build` for a single build or `check` for a build plus native smoke test. Paths
in the config are relative to that config, never to the command's working directory.
Restart `dev` after changing the tool itself or installing dependencies.

## Project contract

Export a config satisfying `ProjectConfig` from `config.d.ts`:

```ts
export default {
  sketches: { particles: 'sketches/particles/main.ts', background: 'sketches/background/main.ts' },
  shaderDirs: ['sketches'],
  generatedDir: 'generated',
  outDir: 'dist',
};
```

All configured directories are inside the project. `generatedDir` belongs to the
generator: obsolete `*.generated.ts` files are removed. The starter's tsconfig
extends `.td/tsconfig.paths.json`, regenerated by the runner from the repository's
import map. Do not commit `.td/`, `generated/`, or `dist/`. Shader wrappers are
written to disk so the IDE sees real types and can navigate to their declarations.

Each entry uses ordinary static imports and exports `draw`, optionally `setup`
and `onPulse`. Use the types from `@avtools/native-webgpu/td-sketch`. `setup(p, host)`
may be async; `draw(p, frame)` and pulse handlers must be synchronous. The output
adapter exposes those exports to the existing TOP loader. Module-local state is
private to the entry's TOP instance and resets on reload.

Import timing functions normally from `@avtools/core-timing`, including in reusable
helpers that do not depend on a TD host. The package implementation is bundled.
The TOP/CHOP recreates its JavaScript environment on activation. `host.timing`
remains a compatibility API for existing scripts. See
[Build, Reload, and Reset](../../packages/native-webgpu/RELOAD.md) for automatic
activation controls, manual restart, errors, and synchronous best-effort cleanup.
Package-authored browser replacements (such as seedrandom's optional crypto
fallback) are honored; this does not add browser APIs to the embedded runtime.

Use `host.device` for raw WebGPU resources; never create a Node GPU or another
renderer. Import `@avtools/power2d/raw`, `/core`, and `@avtools/shader-fx/raw`
explicitly. The broad graphics entry points also export Babylon implementations
and are rejected. A raw scene/effect's final output must currently be RGBA8/BGRA8
to pass into `p.image({texture: outputTexture}, ...)`. Set its format explicitly
to `rgba8unorm`; the raw libraries often default to float textures. Intermediate
raw GPU passes can use their supported formats. This composition stays on the GPU
before the TOP's existing output transfer.

`host.onDispose(() => ...)` registers synchronous cleanup in reverse registration
order, after timing cancellation and before the generation's host handles expire.
It also runs when candidate setup fails, on reset/resize, and on shutdown. Use it
for library `.dispose()` calls and other teardown. Buffers and textures created
through the guarded `host.device` are automatically destroyed at generation end;
explicit destruction removes them from that tracking set. Cleanup errors are logged
and remaining cleanup continues. Asynchronous cleanup is unsupported.

## Shaders

Within each configured shader directory:

| Source suffix | Generated suffix | Existing generator |
| --- | --- | --- |
| `.material.wgsl` | `.material.raw.generated.ts` | Power2D raw material |
| `.strokeMaterial.wgsl` | `.strokeMaterial.raw.generated.ts` | Power2D raw stroke |
| `.fragFunc.wgsl` | `.frag.raw.generated.ts` | shader-fx raw effect |
| `.compute.wgsl` | `.compute.raw.generated.ts` | Raw compute helpers |

Paths retain their project-relative prefix: `sketches/bg/shaders/waves.fragFunc.wgsl`
becomes `generated/sketches/bg/shaders/waves.frag.raw.generated.ts`. Import that
generated module normally. These are the **raw** generator contracts; Babylon
shader signatures are not interchangeable. For complete hand-written shaders,
import a plain `.wgsl` as a string (the starter includes its module declaration).

Generation/TypeScript checks are not a substitute for GPU shader validation. Run
`check` and inspect TD errors when changing actual shader behavior.

## Rebuild and failure semantics

`dev` uses filesystem notifications with a short event debounce, not polling.
Source/helper/WGSL saves trigger generation and checks. It builds all configured
entries but only replaces outputs whose bytes changed, so an unrelated sketch
does not restart. External workspace imports are included. Package `build/`,
`artifacts/`, `node_modules/`, and `.git/` directories are excluded from watching,
so native builds and benchmark logs do not cause repeated TypeScript checks. Config edits are
reloaded too; added entries participate without restarting the watcher.

No output is published until every entry passes generation, typechecking, and
bundling. Each changed bundle is replaced by atomic rename; a failed build leaves
the prior outputs intact. Replacing several bundles is not one TD-wide transaction:
independent TOPs may pick up the changes on different cooks. State is reset, not
hot-patched. Removing an entry from config does not delete its previous bundle or
any TD operators. Source File reload occurs when the TOP cooks; paused or unused
TOPs pick up edits when cooking resumes.

The compatibility checks reject Node built-ins, runtime URL imports, dynamic
imports in checked source, unmanaged core-timing copies, Babylon implementations,
and common unavailable host globals. Arbitrary npm code is not guaranteed portable;
there is no DOM, Node runtime, Deno, or general browser/network environment in the
TOP. Static analysis is intentionally limited, not a security sandbox. The native
check catches exercised runtime/GPU failures, not every possible branch.

Build diagnostics use original source locations. Runtime stacks identify
`td-sketch/<name>.js` and bundled line numbers; original-source runtime stack mapping
is not implemented yet. Bundles remain readable and unminified.

## Verification and maintenance

```sh
npm test
python3 build-example.py
```

Tests cover callbacks, unchanged output timestamps, transitive helper changes,
last-good outputs, unsupported imports/globals, all four shader generators,
deletion, watcher recovery, and resource cleanup. Watch tests need working macOS
filesystem notifications; restricted agent sandboxes may report `EMFILE` even for
one watcher. Run those tests outside that sandbox rather than adding polling.

`check` loads the same plugin runtime and renderer used by TD, creates separate
instances, cooks each 36 times with six source replacements and Trigger pulses,
and writes 320×180 PPM snapshots under `.td/`. It checks reported runtime errors;
it does not require every user sketch to animate or produce nontransparent pixels.
It does not include the TD upload boundary. Set `AVTOOLS_TD_PLUGIN` to test a
specific plugin; otherwise `packages/native-webgpu/prebuilt/macos-arm64/current.txt`
selects the checked-in bundle. The check harness needs Apple Command Line Tools;
normal build/watch does not compile native code.

`build-example.py` uses installed TouchDesigner `toeexpand`/`toecollapse` utilities
to regenerate the checked-in starter artifacts from the integration's existing
example and starter bootstrap. It does not launch or control the TD editor.

`python3 tools/td-sketch-build/benchmark.py 960 2,4` (from the repository root)
loads the starter bundles into two and four 1080p TOPs inside real TouchEngine.
It records TD's per-operator `cpuCookTime`, plugin/worker metrics, and completion
of all output upload fences. Build the starter and native `touchengine-probe`
first. Pause the TD editor preview and avoid other build jobs during measurements.
Results and generated fixtures go under `packages/native-webgpu/artifacts/td/`.
The initial 60 frames and final metrics-export frame are excluded. This is a
buffered-output test with no image inputs; worker elapsed time includes GPU waits
and must not be read as CPU utilization.

## CHOP bundles

The runner also builds the V8/TimeContext CHOP host. Use an object entry with
`{entry: 'sketches/animation/main.ts', target: 'chop', outputs: ['value', 'gain']}`.
Optional `samples` defaults to 1; e.g. `outputs: ['x','y'], samples: 10000` for XY
point buffers. Export `setup`, `onCook`, and/or `onPulse`; setup or onCook is required.
Import types from `@avtools/native-webgpu/td-chop` and launch managed tasks through
`host.timing`. Set the matching Output Channels / Output Samples in TD.

CHOP entries use the same typechecking, import checks, atomic publication, last-good
build behavior, and event-driven watcher. `check` selects the CHOP prebuilt via
`current-chop.txt` (override with `AVTOOLS_TD_CHOP_PLUGIN`) and exercises the configured
channel layout in the embedded V8 host. Mixed TOP/CHOP projects are supported.
See [the channels project](../../apps/td-projects/channels/README.md).
